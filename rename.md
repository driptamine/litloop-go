# Переименование однобуквенных переменных (litloop-go)

Все однобуквенные идентификаторы → человекочитаемые, с проверкой области видимости
(движок: `go run /tmp/rename.go <rules>`, правила: `path|line|old|new`).

## Фаза 0 — Инвентаризация (готово)
AST-обход (`/tmp/listvars.go` → `/tmp/vars.txt`): 1246 мест, исключены
строки/комментарии, найдены 2 места с затенением (учтены).

## Фаза 1 — Правила переименования (готово)
`/tmp/gen_rules2.py` + `/tmp/manual_dict.py` → `/tmp/rules.txt`:
- глобальные: `s→handler/server`, `q→req`, `e→err`, `t→tester`, `p→peer/post/...`
- контекстные: `Message→message`, `o := Object→out`, `b := q.Body()→body`, `i→index` и т.д.
- ~400 точечных правил для неоднозначных случаев.

## Фаза 2 — Движок (готово)
Scope-aware переименование: переименовывает только то, что связано с
целевым объявлением; при конфликте (имя занято / захват чужого use) —
пропускает с пометкой `SKIP`, ничего не ломая.

## Фаза 3 — Прогон по пакетам (текущая)
Порядок: `internal/...` → `chats` → `users` → остальные → `app` (тесты).
После каждого пакета: `go build ./...`, разбор SKIP вручную.

## Фаза 4 — Проверка
`gofmt -l` (чисто), `go vet ./...`, `go test ./...`.
Критерий готовности: ноль однобуквенных объявлений
(`go run /tmp/listvars.go` → пусто, кроме `_`), тесты зелёные.

## Фаза 5 — Коммит (по команде `пуш`)
Одним коммитом, только rename (без функционала), `git status` чистый
кроме пред-existing `M .env.example`.
